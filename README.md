# AI Data Analyst Agent

上传一份表格数据，用中文提问，它自己写 Python 和只读 SQL 去算，把过程摊在界面上；这些问题和结论最后会一起写进 PDF 报告。

## 项目概述

常见的数据分析工具给的是一批固定按钮：画柱状图、做分组统计、看 Top N。真实问题很少正好落在这些按钮上。"哪些因素最影响用户复购"就没有对应按钮，它得先算相关系数，再跑一遍特征重要性，还得比较不同人群的分布。

这个项目不预设分析步骤。用户提问后，模型根据数据画像和问题自己决定下一步：写一段 pandas，或者发一条 SELECT。代码在本地执行，结果原样回传给模型，由它决定继续还是收尾。最终回答只能引用执行结果里出现过的数字。

分工很明确：模型负责想和写，代码负责跑，报告负责留档。

## 项目优势

分析过程能回看。每一步生成了什么代码、有没有报错、打印了什么，都在「分析详情」里。结论对不上时，可以翻回去看是哪一行算的，也可以自己拿去复现。

不编数字。提示词要求只能引用工具结果，执行链路也不给模型编造数字的机会；算不出来它会直说缺什么。

通用，不写死场景。换成销售、运营、问卷、日志数据都能用，不需要改代码，因为没有"红酒专用""电商专用"这类分支。

覆盖面比固定工具宽。取数、分组、排名交给 SQL；相关性、回归、特征重要性、聚类、绘图交给 Python。两边可以接力，先用 SQL 筛出子集，再用 Python 建模。

无关请求挡在前面。闲聊、写诗、翻译、代写代码在意图门这一步就被拒绝，不消耗后面的模型调用，也不会混进报告。

追问不用重复描述。第一轮问"各城市销售额"，第二轮问"只看北京呢"，它知道指的是哪张表、哪些条件。

报告自动累积分析结果。见下一节。

## 报告会把分析结果一起带上

报告不是只有数据长什么样。点 Generate PDF Report 的那一刻，程序把当前会话里每一轮的"问题 + 回答 + 结果表 + 图"按顺序追加到报告后半部分，章节名叫「分析结果」。

报告由两部分构成。

前半部分是数据本身的描述，固定九节：数据集概览、字段与类型、缺失值分析、重复行检查、数值字段统计、类别与离散字段分布、数值字段相关性、数据质量与建议、数据样例。这部分和聊天无关，问多少个问题都一样。

后半部分是这次会话的分析记录，按提问顺序排列。每条包含：当时的问题原文、模型写出的回答、这一步的结果表（前 10 行、最多 8 列）、这一步画出来的图（如果有）。

几个行为需要说明：

- 回答超过 4000 字会被截断，并在末尾标注，避免一次深度分析凑出几十页
- 被意图门挡掉的闲聊不进报告，因为那一轮没有执行任何工具
- 报告是点按钮那一刻的快照，不是边聊边写；生成之后再有新分析，旧 PDF 作废，需要重新点一次
- 换数据集会清空会话，报告也跟着失效

输出链路因此是：提问 → 分析 → 结论留痕 → 一键成文。拿到 PDF 的人能看到三件事：这份数据是什么样、问了什么、算出了什么。

## 项目流程

    上传 CSV / Excel
          ↓
    读取文件 + 生成数据画像（行数、字段类型、缺失、重复、分布）
          ↓
    用户提问
          ↓
    意图判断：这是不是针对当前数据集的分析请求？
          ├─ 否 → 直接拒绝，不执行任何工具
          └─ 是 ↓
    模型决定下一步动作（最多 MAX_STEPS 轮）
          ├─ run_python → 受限沙箱执行，返回结果表 / 图 / 报错
          ├─ run_sql    → 只读校验后查询，返回结果表 / 报错
          └─ done       → 跳出循环
          ↓
    模型只依据执行结果写最终回答
          ↓
    界面渲染：文字结论 / 结果表 / 图表 / 每步代码
          ↓
    写入记忆，支撑下一轮追问
          ↓
    导出 PDF：数据描述 9 节 + 本次会话全部分析

## 用户操作步骤

第 1 步，安装依赖。需要 Python 3.10 以上，我是在 3.13 和 Streamlit 1.66 上测的。

    git clone https://github.com/fqqf11/ai-data-analyst-agent.git
    cd ai-data-analyst-agent
    pip install -r requirements.txt

国内装得慢可以换镜像：

    pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

第 2 步，启动。

    streamlit run app.py

第 3 步，浏览器打开 http://localhost:8501 。这个终端窗口别关，关了服务就停。

第 4 步，左侧栏填配置。粘贴 DeepSeek API Key（在 platform.deepseek.com 创建），模型保持 deepseek-chat，「最大分析步数」默认 8；简单问题填 3 到 4 步更省钱，复杂分析再调大。

第 5 步，上传数据。点「上传数据集」选 CSV 或 Excel。传完会出一个「Dataset overview」面板，先扫一眼行数、列数、重复行、缺失率、字段类型；有异常最好先处理数据再提问。

第 6 步，提问。底部输入框里写问题，回车。简单查询十几秒，复杂分析可能要一分钟。

第 7 步，看结果。回答、结果表、图表都在对话里；展开「分析详情」能看到每一步的代码和原始输出。

第 8 步，继续追问。同一份数据不用重新上传，直接接着问，之前筛过的条件会被带上。

第 9 步，导出报告。页面往下滚到「导出报告」，点 Generate PDF Report，再点下载。报告里包含数据描述和这一轮会话的全部分析。

仓库自带一份样例，可以先拿它跑通流程再换自己的数据：

    data/wine_sample.csv        1596 行红酒理化指标 + 质量评分
    reports/example_report.pdf  用当前版本生成的示例报告

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 空 | 界面上填也行，写进 `.env` 只是不用每次填 |
| `DEEPSEEK_MAX_STEPS` | `8` | 一轮提问最多执行几步。3 到 4 步够用，12 以上明显变贵 |

`.env` 已在 `.gitignore` 里，不会被提交。

## 目录结构

    app.py          Streamlit 界面：上传、Key、提问、渲染、导出 PDF
    agent.py        主循环：意图判断 → 决策 → 执行 → 回答 → 写记忆
    deepseek.py     DeepSeek 客户端，全项目只从这里调模型
    executor.py     执行层：run_python 沙箱、run_sql 只读
    prompts.py      四个提示词：系统规则、意图判断、决策、最终回答
    data_utils.py   读 CSV / Excel，生成数据画像
    tools.py        SQL 只读校验 + DuckDB 执行
    memory.py       会话历史和分析上下文
    report.py       PDF 报告：数据描述 + 分析结果
    data/           样例数据（自己的数据放这里也不会入库）
    reports/        生成的图表和报告

依赖是单向的：app.py → agent.py → executor.py → tools.py，agent.py 另外用到 deepseek.py、prompts.py、memory.py。想调整回答风格或规则，基本都在 prompts.py 里改。

## 能问什么

适合的问题：

- 分组、排名、趋势：各城市销售额排名、近 6 个月订单量变化
- 分布、异常：消费金额分布如何、找出偏离 3 个标准差的记录
- 归因、相关性：哪些因素最影响复购、价格和评分有关系吗
- 统计建模：做一次线性回归预测销售额，给出各变量系数
- 可视化：画一张各渠道复购率柱状图

会被拒绝的：闲聊、写诗、翻译、通用知识问答、代写代码。它只分析你上传的那份数据。

提问技巧：一次问一件事；把指标和维度说清楚，"按城市统计平均客单价"比"看看数据"好得多；结果不满意就接着问，比如"换成随机森林再看一次重要性"。

## 已知限制

- run_python 在进程内执行。白名单 import、去掉 open / eval / exec 这类内置函数、25 秒超时，能挡住误操作，挡不住刻意构造的逃逸（比如顺着函数对象的 __globals__ 摸出去）。自己用或者给可信的人用没问题，公开给陌生用户之前得换成子进程或容器隔离。
- SQL 只读。validate_sql 会先剥掉字符串字面量和注释再检查关键字，写操作和多语句都会被拒。
- 数据在本地读取和执行，但执行结果（包含结果表的前若干行）会随着提示词发给 DeepSeek，这一点和"纯本地分析"不同。
- 数据会复制一份进沙箱，几十万行还行，上百万行内存会吃紧，步数多了更明显。
- 每次 SQL 都新建 DuckDB 连接并重新注册视图，单次几十毫秒，连着问很多次时会有点拖。
- 结论对不对取决于模型代码写得对不对。好在结果表和执行记录都摆在界面上，可以核对。
- 一轮提问通常 2 到 10 次模型调用，步数调大费用跟着涨。

## 常见问题

- 报缺 openai：pip install openai
- 模型调用失败：Key 失效、额度用完，或者网络不通
- CSV 读不出来：用 Excel 另存成 UTF-8 的 CSV 再试
- Excel 读不了：多半是没装 openpyxl
- 等太久：把最大步数调到 3 到 4，或者先抽样
- 图表中文变方块：程序会去系统字体里找雅黑和黑体，机器上没中文字体就得自己装一个
- 关掉终端网页就打不开：服务跟着终端一起退了，重新运行 streamlit run app.py
