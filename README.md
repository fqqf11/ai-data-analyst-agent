# AI Data Analyst Agent

上传一份表格数据，用中文提问，它自己写 Python 和只读 SQL 去算，过程摊在界面上；这些问答最后会一起写进 PDF 报告。

## 这个项目和固定工具的区别

固定工具的思路是：先想好一批分析类型，给每类配一个函数，用户问题去匹配类型。稳定、快，代价是覆盖不到没预设的情况。

最早我就是这么写的，用关键词匹配选工具，命不中就什么都不出。"哪些因素影响复购"这种问题，既不算排名也不算趋势，关键词表里没有对应项，直接哑火。

现在的做法是把写代码这件事交给模型。给它数据画像和已执行的步骤，它选下一步：写 Python、发 SQL、或者收尾。执行结果原样回传，直到它认为够了。换来的是通用性，代价是延迟和 token：一次提问通常 2 到 10 次调用，简单的十几秒，复杂的一分钟。

两种路线没有绝对的好坏。样本固定、问题反复问的场景，固定工具更划算；字段经常换、问题开放，让模型现场写代码更省事。

## 几个实际的好处

执行记录是完整的。每步的代码、报错、stdout 都在「分析详情」里，能复制出来自己跑一遍。排查"这个数怎么来的"时很有用——模型的解释可能是错的，代码不会。

数字有来源。写回答时只允许引用工具结果里出现过的数值；沙箱里也没有联网和读写文件的通道，想编都缺少材料。

SQL 只读是校验出来的，不是嘴上保证的。validate_sql 先剥掉字符串字面量和注释，再查关键字，最后才交给 DuckDB。多语句、写操作、拿注释绕开，我都试过，能拦住。

闲聊不消耗调用。意图判断排在最前面，一次调用决定是不是数据分析请求，不是就直接返回，后面的循环一步都不走。顺带的好处是报告里不会混进无关问答。

追问能接上。第一轮筛过的城市、渠道记在 memory 里，第二轮只说"只看北京呢"，改写阶段会把条件补回去，不用重述。

## 报告不只是数据描述

基础部分是九节固定的数据描述：概览、字段与类型、缺失、重复、数值统计、类别与离散分布、相关性、质量建议、样例。这部分和对话无关，问多少问题都一样。

真正让报告有用的在后半段。点 Generate PDF Report 的那一刻，程序把当前会话里每一轮的问答按顺序追加进去：问题原文、模型写出的回答、那一步的结果表（前 10 行、最多 8 列）、以及画出来的图。章节名就叫「分析结果」。

所以别人拿到 PDF 能看到两件事：这份数据本身有什么问题（缺失率、重复行、哪几个字段相关），以及你问过什么、算出了什么。不用再把聊天记录截图贴进去。

有几处行为容易被误解，提前说明：

- 报告是点按钮那一刻的快照。生成之后再提问，旧 PDF 就过期了，得重新点
- 被意图门拦掉的闲聊不进报告——那一轮没有执行任何工具，没有结果可写
- 回答超过 4000 字会截断并标注，否则一次深度分析能凑出几十页
- 换数据集会清空会话，报告一并失效

## 项目流程

    上传 CSV / Excel
          ↓
    读取文件 + 生成数据画像（行数、字段类型、缺失、重复、分布）
          ↓
    用户提问
          ↓
    意图判断：这是不是针对当前数据集的分析请求？
          ├─ 否 → 直接拒绝，不执行任何工具
          └─ 是 ↓
    模型决定下一步动作（最多 MAX_STEPS 轮）
          ├─ run_python → 受限沙箱执行，返回结果表 / 图 / 报错
          ├─ run_sql    → 只读校验后查询，返回结果表 / 报错
          └─ done       → 跳出循环
          ↓
    模型只依据执行结果写最终回答
          ↓
    界面渲染：文字结论 / 结果表 / 图表 / 每步代码
          ↓
    写入记忆，支撑下一轮追问
          ↓
    导出 PDF：数据描述 9 节 + 本次会话全部分析

## 用户操作步骤

第 1 步，装依赖。需要 Python 3.10 以上，我是在 3.13 和 Streamlit 1.66 上测的，更老的版本没试过。

    git clone https://github.com/fqqf11/ai-data-analyst-agent.git
    cd ai-data-analyst-agent
    pip install -r requirements.txt

装得慢就换镜像：

    pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

第 2 步，启动。

    streamlit run app.py

第 3 步，浏览器打开 http://localhost:8501 。终端窗口别关，关了服务就停。

第 4 步，左侧栏填配置：粘贴 DeepSeek API Key（在 platform.deepseek.com 创建），模型保持 deepseek-chat，「最大分析步数」默认 8。简单问题填 3 到 4 步更省钱，复杂分析再调大。

第 5 步，上传 CSV 或 Excel。传完会出现「Dataset overview」面板，先看一眼行数、列数、重复行、缺失率和字段类型；类型不对或缺失太高的列，最好先处理再提问。

第 6 步，提问。底部输入框写问题，回车。简单查询十几秒，复杂分析可能要一分钟。

第 7 步，看结果。回答、结果表、图表都在对话里；展开「分析详情」能看到每一步的代码和原始输出。

第 8 步，继续追问。同一份数据不用重传，直接接着问，之前筛过的条件会被带上。

第 9 步，导出报告。滚到页面下方「导出报告」，点 Generate PDF Report，再点下载。

仓库自带一份样例，可以先用它跑通流程：

    data/wine_sample.csv        1596 行红酒理化指标 + 质量评分
    reports/example_report.pdf  用当前版本生成的示例报告

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 空 | 界面上填也行，写进 `.env` 只是不用每次填 |
| `DEEPSEEK_MAX_STEPS` | `8` | 一轮提问最多执行几步。3 到 4 步够用，12 以上明显变贵 |

`.env` 已在 `.gitignore` 里，不会被提交。

## 目录结构

    app.py          Streamlit 界面：上传、Key、提问、渲染、导出 PDF
    agent.py        主循环：意图判断 → 决策 → 执行 → 回答 → 写记忆
    deepseek.py     DeepSeek 客户端，全项目只从这里调模型
    executor.py     执行层：run_python 沙箱、run_sql 只读
    prompts.py      四个提示词：系统规则、意图判断、决策、最终回答
    data_utils.py   读 CSV / Excel，生成数据画像
    tools.py        SQL 只读校验 + DuckDB 执行
    memory.py       会话历史和分析上下文
    report.py       PDF 报告：数据描述 + 分析结果
    data/           样例数据（自己的数据放这里也不会入库）
    reports/        生成的图表和报告

依赖单向：app.py → agent.py → executor.py → tools.py，agent.py 另外用 deepseek.py、prompts.py、memory.py。想改回答风格或规则，基本都在 prompts.py 里。

## 能问什么

适合的问题：

- 分组、排名、趋势：各城市销售额排名、近 6 个月订单量变化
- 分布、异常：消费金额分布如何、找出偏离 3 个标准差的记录
- 归因、相关性：哪些因素最影响复购、价格和评分有关系吗
- 统计建模：做一次线性回归预测销售额，给出各变量系数
- 可视化：画一张各渠道复购率柱状图

会被拒绝的：闲聊、写诗、翻译、通用知识问答、代写代码。它只分析你上传的这份数据。

提问技巧：一次问一件事；把指标和维度说清楚，"按城市统计平均客单价"比"看看数据"好得多；结果不满意就接着问，比如"换成随机森林再看一次重要性"。

## 已知限制

- run_python 在进程内执行。白名单 import、去掉 open / eval / exec 这类内置函数、25 秒超时，能挡住误操作，挡不住刻意构造的逃逸（比如顺着函数对象的 `__globals__` 摸出去）。自己用或者给可信的人用没问题，公开给陌生用户之前得换成子进程或容器隔离。
- SQL 只读靠 validate_sql 兜底，写操作和多语句都会被拒；但不做行列级权限控制，能查的字段就是上传文件里的全部字段。
- 数据在本地读取和执行，但执行结果（含结果表前若干行）会随提示词发给 DeepSeek，这一点和"纯本地分析"不一样。
- 数据会复制一份进沙箱，几十万行还行，上百万行内存吃紧，步数多了更明显。
- 每次 SQL 都新建 DuckDB 连接并重新注册视图，单次几十毫秒，连着问很多次会有点拖。
- 结论对不对取决于模型代码写得对不对。好在结果表和执行记录都摆在界面上，可以核对。
- 一轮提问通常 2 到 10 次模型调用，步数调大费用跟着涨。

## 常见问题

- 报缺 openai：pip install openai
- 模型调用失败：Key 失效、额度用完，或者网络不通
- CSV 读不出来：用 Excel 另存成 UTF-8 的 CSV 再试
- Excel 读不了：多半是没装 openpyxl
- 等太久：把最大步数调到 3 到 4，或者先抽样
- 图表中文变方块：程序会去系统字体里找雅黑和黑体，机器上没中文字体就得自己装一个
- 关掉终端网页就打不开：服务跟着终端一起退了，重新运行 streamlit run app.py
